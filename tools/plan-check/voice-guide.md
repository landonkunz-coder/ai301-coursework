# Voice guide: how I talk upstream

## Who I am in threads

I'm Landon, a CodePath AI301 student, and this is my first open source contribution.
I work one issue at a time: claim it, reproduce it, then fix it.
Expect short comments with the exact commands I ran and the output I got.

## Rules I write by

### Rule: no promised timelines

I promise the next thing I'll post, never a date or how fast it will happen.

- Wrong: "I will fix this by tomorrow, promise!!"
- Right: "Repro report on the way."

### Rule: name the version and the behavior

Every comment says what I ran it on and exactly what happened, so it could only belong to this issue.

- Wrong: "I can confirm this bug."
- Right: "On commit 2f4e82f, verify_password raises UnknownHashError on a malformed stored hash instead of returning False."

### Rule: say it like I would out loud

If I wouldn't say it to someone's face, it doesn't go in the comment. No hype, no bot voice.

- Wrong: "Hi!! So excited to contribute to this amazing project!!"
- Right: "Picking this up. First contribution, so flagging that."

### Rule: no em dashes

I use periods and commas. No em dashes anywhere in a comment.

- Wrong: "Picking this up — repro report soon."
- Right: "Picking this up. Repro report on the way."

### Rule: don't invent claims

I only say I did something if the output is in the comment. Before I run it, I say what I will do, not what I found.

- Wrong: "I reproduced this and I know what the fix is."
- Right: "I haven't run it yet. I'll post the command and the output when I do."

## Things I never post

- A date or time frame ("by tomorrow", "shortly", "within 2 days")
- "+1", "any update?", or "please assign me"
- A reproduction, root cause, or fix I haven't shown output for
- Em dashes
- Filler like "Great catch!" or "Hope this helps!"
