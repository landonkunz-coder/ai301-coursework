## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | The repro report's environment record. | The report states (a) the project version, tag, or commit tested, (b) the OS or platform it ran on, and (c) if the tool runs through a language runtime (Python, Node), that runtime's version. If the issue names a target version and the report tested a different one, the report says so. Missing any required item fails. | required |
| steps-followable | The repro report's steps, read as a stranger starting from the point the report names (e.g. a fresh clone). | Every action between that starting point and the shown output is given as an exact command or exact input. Each input file or data the trigger uses is shown, taken verbatim from the issue (and the report says so), or described precisely enough to recreate it (every element that triggers the bug is named). A step described only in prose with no command ("ran the tool on a file", "set it up normally") fails, and so does an input a stranger cannot obtain (a private repo, an internal config, an unnamed download). If the report names no starting point, start from the tool or project installed at the version its environment record states. | required |
| outcome-evidenced | The repro report's stated outcome, read against the output it pastes. | The report states one outcome explicitly (reproduced, or could not reproduce), and the run that outcome rests on has pasted output (terminal text, log, or test result). Side observations (repeat runs, a control variant, a second version) may be described in prose without their own output. A stated outcome with no pasted output behind it fails. Whether the output matches the issue is graded by behavior-matches, not here. | required |
| behavior-matches | The pasted output, read against the failure the issue describes (its error name, message, exit code, or wrong value). | If the report says reproduced: the output shows the same failure the issue names. A different or adjacent error fails. If the report says could not reproduce: the output comes from running the issue's own trigger (or, when the issue gives no exact command, a run built from the conditions the issue describes) and shows it not failing, and the report names what differed from the issue's environment or conditions. An attempt that honestly states it may not have met every condition the issue describes still passes; this branch fails only when the report claims a match or a non-failure its output does not show. | required |
| conventions-respected | The repo's rules for contributors (AI-assistance disclosure, required templates or formats): in eval mode the repo-facts block; in live mode the repo's CONTRIBUTING, AGENTS.md, README, and .github/ templates (see the evidence guide's Comms section). Read against every comment in the package. | Every requirement those rules explicitly state for issue comments is met. Count only what the policy says about comments: rules about pull requests or code, and conditions a reader cannot check from the text ("must understand the work"), impose nothing here. A policy that allows AI use without asking for disclosure requires no disclosure. If the policy requires disclosure in every comment, each comment must disclose; otherwise one disclosure in the package covers it. If the rules state no such requirement, pass. | required |
| claim-specific | The claim comment, read against the issue. | The claim names something specific to this issue (the function, error, or behavior) and says what the author will produce next (e.g. a repro report). It does not state work as done that the package does not show (e.g. "I have reproduced this" with no output behind it) and promises no date or time frame ("shortly", "by tomorrow"). A claim that could be pasted on any issue fails. | required |

## Verdict rule

Accept if every required check passes; otherwise reject. `unclear` on a required check counts as fail. Preferred checks never change the verdict. In a live-mode claim-only draft, the report-side checks (env-recorded, steps-followable, outcome-evidenced, behavior-matches) are reported as not yet applicable and left out of the verdict, as SKILL.md directs.
