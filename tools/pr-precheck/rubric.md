# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| scope-faithful | The diff's changed files and hunks (eval: the Diff; live: `git diff main...HEAD`) read against the plan's scope, its "Files:" line, its not-in-scope line, and its deviation notes (eval: Plan context; live: `plan.md` including `## Deviations`). Also the plan's in-scope changes read back against the diff. | Pass if (a) every changed file is named by the plan, by its folder, or by a deviation note in the plan or the description (a planned "changelog entry" names the changelog file; planned tests under a folder name test files in that folder), and (b) every change the plan puts in scope is in the diff, or its absence is stated in the description or the deviation notes. Fail if any changed file or hunk falls outside the plan with no note anywhere, or a planned change is missing with no note. A disclosed shortfall passes. | required |
| description-true | Every factual claim in the title and description, including checklist items and Changes bullets (eval: Candidate PR title and description; live: `pr_draft.md`), read against the diff and the test evidence. | Pass if every claim about what the PR changes, adds, tests, or leaves out is true of the diff: files, fixtures, and tests the description says were added appear in the diff; fidelity claims ("implements the plan exactly", "no other changes") hold; a claim that something was not added holds when nothing in the diff adds it; ticked boxes are true. Fail if any such claim is contradicted by the diff or has nothing in the diff behind it. Rationale and opinion are not claims. | required |
| tested | The test evidence (eval: the Test evidence block and any testing text in the description; live: the description's Testing section, confirmed against `test_evidence.md`) read against the plan's test plan and the checks the repo's PR template lists. | Pass if (a) the issue's own reproduction (its steps or input, not only a control or a different case) is re-run on the change, and the PR shows the command or steps with a concrete observed after result (printed output, or a stated value, exit code, message, or on-screen behavior) that shows the fixed behavior the plan or issue expects (the before may be quoted from the posted repro), and (b) every other check the plan's test plan or the repo's template names is reported with its outcome, where a failing or not-run check passes when the reason is stated. Fail if the reproduction's after run is missing, if only a control or a different input was run, if the after result is vague ("works now", "fixed", "tests pass") with no concrete observed result, if it does not show the fix, or if a named check is never mentioned. Not required: output pasted verbatim (a concrete result stated in a comment after the command counts); printed output for checks other than the reproduction; tests beyond what the plan names; CI results, since CI runs after the PR opens. | required |
| clean-diff | Every hunk in the diff (eval: the Diff; live: `git diff main...HEAD`). | Pass if every hunk is part of the fix, its tests, its docs or changelog, an edit the repo's own rules require for this fix (such as removing the issue's xfail marker), or a change the fix needed that the plan or description records. Fail if any hunk is debug output, commented-out code, reformatting of lines the fix does not otherwise change, or a change the issue does not need, even when the description discloses it. | required |
| template-met | The repo's stated PR template and contribution policy (eval: the Repo facts "pull requests" and "contribution policy" lines; live: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md` on `main`) read against the title and description. | Pass if every section and checklist item the template asks for is present with real content ("N/A" with a reason counts; an honestly unticked box counts), the issue is referenced where the template asks, and every stated policy ask (such as an AI disclosure where the policy requires one) is met. Pass if the repo states no template or policy. Fail if a stated ask is missing or visibly ignored: an empty section, template placeholder text left in, or a required disclosure absent. Not required: anything the repo does not state. | required |

## Verdict rule

Accept if every required check passes. Reject if any required check
fails or is unclear: `unclear` counts as `fail`, because a PR that
cannot be verified from the package is not ready to submit. There are
no preferred checks; if one is added, it never changes the verdict. A
check whose pass condition covers a disclosed shortfall grades `pass`
when the shortfall is disclosed, so an honest, partial PR can be
accepted.
